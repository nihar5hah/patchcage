## What we changed for PatchCage

- Nested `cli/.git` is removed so this is a vendor tree, not a submodule.
- Nested `cli/.husky` and the root `"prepare": "husky"` script are removed. Always `npm install --ignore-scripts` in this directory so husky cannot install into the parent PatchCage repo.
- Dropped `packages/server` and `packages/evals` (and the root `eval` script). Restore them from upstream if you need those packages.
- Example-extension workspaces are not installed (files remain under `packages/coding-agent/examples/extensions/`).
- Root `build` / `build:offline` skip `session-backends/sqlite-node` and `packages/server`. sqlite-node source is kept for upstream tracking.
- Coding-agent `piConfig.name` is `patchcage`, `piConfig.configDir` is `.patchcage`, bin is `patchcage`. npm package name stays `@earendil-works/pi-coding-agent`.
- Root `package-lock.json` must not keep stale `packages/evals` / `packages/server` entries after those trees are dropped. After a strip, regenerate coding-agent lock artifacts with `npm run shrinkwrap:coding-agent` and `npm run install-lock:coding-agent` (then `--check` both). Those files copy `bin` from `packages/coding-agent/package.json`.
- Root `tsconfig.json` drops the deleted `pi-agent-old` paths. `packages/coding-agent/examples/extensions/gondolin/**` and `with-deps/**` are excluded from `tsgo` because those example workspaces are not installed.
- `packages/coding-agent` `build:binary` outfile is `dist/patchcage`. That script is not on the default `npm run build` path.

## Privacy / network (unchanged upstream defaults)

Interactive start can still hit `https://pi.dev/api/latest-version` and install telemetry. `update --self` can nag toward installing upstream `@earendil-works/pi-coding-agent`. Print-mode (`--print --no-tools --no-session`) does not hit those paths.

Mitigations (do not change default telemetry in this vendor cut):

- `--offline` or `PI_OFFLINE=1` skips the version check and other gated network.
- `PI_TELEMETRY=0` disables install telemetry when the env flag is set (see `isInstallTelemetryEnabled`). Settings also expose `enableInstallTelemetry`.
- `packages/tui` fallback when no `logDirectory` is passed: `PATCHCAGE_CODING_AGENT_DIR`, then `PI_CODING_AGENT_DIR`, then `~/.patchcage/agent`. In-tree PatchCage callers still pass `getAgentDir()`.

## Config dirs (intended coexistence)

Do not rename these in this cut:

| Path | Owner |
| --- | --- |
| `~/.patchcage/agent/` (or `PATCHCAGE_CODING_AGENT_DIR`) | Agent secrets and user config (`auth.json`, sessions) |
| `<cwd>/.patchcage/runs/` | Engine evidence bundles |
| `<cwd>/.patchcage/settings.json` (and npm/git/extensions) | Agent **project** config if you run the TUI in that repo |

The parent `.gitignore` ignores `.patchcage/` wholesale. Engine policy treats `.patchcage/` as a control dir. Secrets stay under `~/.patchcage/agent/` unless cwd is `$HOME`.

`npm-shrinkwrap.json` and `install-lock/` pin **upstream** registry tarballs (`@earendil-works/pi-*@0.84.4`). They keep `check` green and copy `bin.patchcage` from this tree; they are not a publishable PatchCage package. Do not `npm ci` from `install-lock/` expecting vendored sources.

## Upgrade notes

1. Fetch the desired upstream SHA: `git clone --depth 1` then `git rev-parse HEAD`, or `git fetch` + checkout in a throwaway clone.
2. Diff this tree against that SHA, re-apply the PatchCage strip/rebrand above, and keep `LICENSE`.
3. First build after a clone **must** be `npm run build` (not `build:offline`): `packages/ai/src/providers/data/` is gitignored and is generated by `generate-models`.
4. Do not run `npm install` without `--ignore-scripts` until you have confirmed there is no nested `.git` and no `prepare`/husky hook that would touch the parent repo.
5. Do not run the upstream `eval` / `publish` / `local-release` scripts unless you have restored `packages/server` and `packages/evals`.

## Verified at pin

- `node packages/coding-agent/dist/bundle/cli.js --help` prints `patchcage`, not `pi`.
- Print-mode smoke against local Ollama (`http://127.0.0.1:11434/v1`, dummy `apiKey`) used `gpt-oss:120b-cloud`. That tag is **cloud-routed**: Ollama on localhost still proxies the request to ollama.com. Several other `*-cloud` tags listed in `ollama list` (`glm-4.6:cloud`, `glm-4.7:cloud`, `qwen3-coder:480b-cloud`, …) return HTTP 410 retired. This machine still has **only** `:cloud` tags; llama.cpp `:8080` is empty. Phase 4 "local model" means the OpenAI-compatible endpoint was localhost; the weights for that smoke were not. To re-verify with on-machine weights, install a tag **without** `:cloud` (do not pull a large model just for this), add it to `~/.patchcage/agent/models.json`, and rerun print-mode as in the root README Status section. The CLI has no `--base-url`.

## Expected-red coding-agent vitest

`cd packages/coding-agent && npx vitest run` is **not** green after the PatchCage rebrand. Do not rewrite the upstream suite to match. Failures fall into two buckets:

1. **Rebrand.** Tests still assert `.pi`, `PI_CODING_AGENT_DIR`, `"not a valid pi session"`, or the upstream `pi` bin name. Those strings are intentionally `patchcage` / `.patchcage` / `PATCHCAGE_CODING_AGENT_DIR` in this tree.
2. **Host tools.** A few files (`tools.test.ts`, regressions 3302/3303) need `fd` on PATH. That is an upstream test dependency, not a PatchCage omission.

`packages/tui` node tests are green.
